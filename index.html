JSON:API,
fluent in Swift.

Vox is a Swift implementation of JSON:API 1.1 for iOS, macOS, tvOS, watchOS and Linux. Resources are classes whose properties read and write the JSON of their document, and data sources send JSON:API requests with async/await.

Get started What is JSON:API?
Articles.swift
let api = URL(string: "https://example.com/")!
let articles = DataSource<Article>(
    strategy: .path("articles/<id>"),
    client: URLSessionClient(baseURL: api)
)

let document = try await articles
    .fetch()
    .include(["author"])
    .sort([.descending("publishedAt")])
    .result()

for article in document.data ?? [] {
    print(article.title ?? "", article.author?.firstName ?? "")
}

The specification

A specification for building APIs in JSON

If you’ve ever argued with your team about the way your JSON responses should be formatted, JSON:API can help you stop the bikeshedding and focus on what matters: your application.

JSON:API describes how a client should request that resources be fetched or modified, and how a server should respond to those requests.

Fewer requests, less data

JSON:API is designed to minimize both the number of requests and the amount of data sent between clients and servers, without compromising readability, flexibility, or discoverability.

Shared conventions

By following shared conventions, you can increase productivity, and take advantage of generalized tooling and best practices, on the server and in every client.

Built for caching

Clients built around JSON:API can take advantage of its features around efficiently caching responses, sometimes eliminating network requests entirely.

Reads and writes

JSON:API covers creating, updating and deleting resources and their relationships as well, not just responses, down to the status codes.

Media type

Registered with the IANA

JSON:API documents are exchanged with their own media type. Its only parameters are ext and profile, which list the URIs of the extensions and profiles a document uses: extensions add to the specification, and profiles share a particular usage of it.

Vox sends Accept: application/vnd.api+json with every request, and the same Content-Type with every body. Headers set on a request replace them, for example to ask for an extension.

Top level

A JSON object is at the root of every document. It contains at least one of data, the primary data, errors, an array of error objects, or meta, non-standard meta-information. data and errors never appear together.

A document can also have jsonapi, which describes the server’s implementation, links for the document as a whole, and included, the related resources.

Vox
let document = try Deserializer.Collection<Article>()
    .deserialize(data: data)

document.data     // [Article]?
document.links    // Links?
document.meta     // [String: Any]?
document.jsonapi  // [String: Any]?
document.included // [[String: Any]]?

Primary data

The primary data represents the resource or the collection that the request targets. For a single resource, it’s a resource object, a resource identifier object or null.

A collection is always an array, even when it holds one resource or none.

Vox
// "data": [ ... ]
let collection = try Deserializer.Collection<Article>()
    .deserialize(data: data)
collection.data // [Article]?

// "data": { ... } or "data": null
let single = try Deserializer.Single<Article>()
    .deserialize(data: data)
single.data     // Article?

Type and id

Every resource object has a type and an id, and within an API, the pair identifies a single, unique resource. Both are strings. Resource identifier objects, the linkage of relationships, carry the same pair.

Only a resource that’s created on the client can leave out its id. It can carry a local lid instead.

Vox
article.type // "articles", the resourceType of Article
article.id   // "1"

// people/9 wrote the article and comment 12,
// and it has a single instance:
article.author === article.comments?[1].author // true

Attributes

The attributes object holds the resource’s data, as any JSON value, including objects and arrays. Keys that refer to other resources, such as author_id, belong in relationships instead.

Attributes and relationships are the fields of a resource. They share one namespace with type and id, so no field is named type or id, and an attribute and a relationship never have the same name.

Vox
article.title      // "JSON:API paints my bikeshed!"
article.attributes // ["title": "JSON:API paints my bikeshed!"]

article.title = "JSON:API paints my Swift bikeshed!"

Relationships

A relationship object describes a to-one or a to-many relationship. Its links can have a self link, for the relationship itself, and a related link, for the related resources.

Its data is the resource linkage: null or [] when the relationship is empty, and resource identifier objects otherwise.

Vox
article.author?.firstName // "Dan", from included
article.comments?.count   // 2

let author = article.relationship(named: "author")
author?.links?.related?.url // .../articles/1/author
author?.hasData             // true

Links

Links appear at the top level, in resource objects and in relationship objects. A link is a URL string, or a link object with an href and other members, such as meta.

At the top level, self refreshes the document, and first, last, prev and next page through the collection.

Vox
document.links?.next?.href   // ".../articles?page[offset]=2"
article.links?.selfLink?.url // http://example.com/articles/1

// Documents fetched by a data source follow them:
let nextPage = try await page.next?.result()

Included resources

A compound document carries related resources in a top-level included array, so the client gets the article, its author and its comments with one request.

Every included resource is reached through a chain of relationships from the primary data, which is called full linkage. Clients ask for related resources with the include parameter.

Vox
// GET /articles?include=author,comments
let page = try await articles
    .fetch()
    .include(["author", "comments"])
    .result()

// Relationships resolve from included when they're read
page.data?.first?.author?.twitter // "dgeb"

Resources

Classes that are views of JSON

A resource is a subclass of Resource. The class declares the JSON:API type, and its properties declare the attributes and relationships. The properties don’t store values: they read and write the resource’s JSON, so a resource is a typed view of its resource object.

Resources.swift · Apple platforms
import Vox

final class Article: Resource {
    override class var resourceType: String { "articles" }

    @objc dynamic var title: String?
    @objc dynamic var publishedAt: Date?
    @objc dynamic var viewCount: NSNumber?
    @objc dynamic var author: Person?
    @objc dynamic var comments: [Comment]?
}

final class Person: Resource {
    override class var resourceType: String { "people" }

    @objc dynamic var firstName: String?
    @objc dynamic var lastName: String?
    @objc dynamic var twitter: String?
}

final class Comment: Resource {
    override class var resourceType: String { "comments" }

    @objc dynamic var body: String?
    @objc dynamic var author: Person?
}
Resources.swift · every platform, including Linux
import Vox

final class Article: Resource {
    override class var resourceType: String { "articles" }

    @Member var title: String?
    @Member var publishedAt: Date?
    @Member var viewCount: Int = 0
    @Member var author: Person?
    @Member var comments: [Comment]?
}

final class Person: Resource {
    override class var resourceType: String { "people" }

    @Member var firstName: String?
    @Member var lastName: String?
    @Member var twitter: String?
}

final class Comment: Resource {
    override class var resourceType: String { "comments" }

    @Member var body: String?
    @Member var author: Person?
}
  1. 01
    The type is the classresourceType is the JSON:API type. A class that doesn’t override it uses the name of the class.
  2. 02
    Relationships by declarationA property typed as a Resource subclass is a to-one relationship, and an array of them is a to-many relationship. Declared as Resource, a relationship holds any type.
  3. 03
    Everything else is an attributeStrings, numbers, Booleans, dates as ISO 8601 strings, URLs, and arrays and dictionaries of JSON values.
  4. 04
    Every platform@objc dynamic properties use the Objective-C runtime. @Member properties work on Linux too, with Swift types such as Int and an initial value.
  5. 05
    Your names, their membersMembers named differently than their property are mapped with codingKeys.
Fetching data

Ask for exactly what you need

JSON:API reserves query parameters for related resources, sparse fieldsets, sorting, pagination and filtering. Build a request, and see the URL that Vox sends for it.

Endpoint
include Inclusion of related resources
fields Sparse fieldsets
articles
people
sort Click again for descending
filter Filtering
filter[]=
page Pagination
number size offset limit cursor
HTTP request
fields filter include sort page
Swift

Vox sends the parameters in a fixed order: sparse fieldsets sorted by type, the filter, include, sort and the pagination. The same request always has the same URL.

include

Inclusion of related resources

A comma-separated list of relationship paths, such as comments.author. The response is then a compound document with an included member, even when it’s empty.

include adds paths, leaving out the ones included already.

fields[TYPE]

Sparse fieldsets

Limits the fields of each type in the response to a comma-separated list. An empty value asks for no fields of the type.

fields merges the fieldsets of each type.

sort

Sorting

Comma-separated sort fields, applied in order. Each is ascending unless it starts with a minus. Dotted fields such as author.lastName sort by related attributes.

.ascending("title") and .descending("publishedAt").

filter · page

Filtering and pagination

The filter and page families are reserved for them, whatever strategy the server uses: page[number], page[offset] or page[cursor].

Filter, and page-, offset- and cursor-based Pagination.

Pagination links

Pages that know their neighbors

Pagination links go in the links object of the collection they page. A link that isn’t available is left out or null.

first.first
prev.previous
next.next
last.last
Vox
let page = try await articles
    .fetch()
    .paginate(Pagination.PageBased(number: 1, size: 20))
    .result()

// Follows links.next, or is nil without it
let nextPage = try await page.next?.result()

// Or grow one document, page by page
if let pagination = try await page.appendNext() {
    pagination.new // the resources that were appended
    pagination.all // the document's data now
}
Creating, updating and deleting

Writes are documents too

Requests that change resources send a document with the JSON:API media type. A request completely succeeds or fails, in a single transaction: there are no partial updates.

A resource is created with a POST to its collection. The resource object needs a type, and the server usually assigns the id. Relationships in the request set the linkage of the new resource.

HTTP request
POST /articles HTTP/1.1
Content-Type: application/vnd.api+json
Accept: application/vnd.api+json

{
  "data": {
    "type": "articles",
    "attributes": {
      "title": "Hello, world"
    },
    "relationships": {
      "author": {
        "data": { "type": "people", "id": "9" }
      }
    }
  }
}
Swift
let draft = Article()
draft.title = "Hello, world"
draft.author = dan // a Person whose id is "9"

// POST articles
let created = try await articles.create(draft).result()
created?.data?.id // the id the server assigned
201
CreatedThe server changed the resource, for example by assigning an id, and returns it.
202
AcceptedThe request is accepted, but its processing isn’t complete yet.
204
No ContentThe resource was created as it was sent. Vox returns nil.
403
ForbiddenThe request is unsupported, for example because of a client-generated id.
404
Not FoundA related resource doesn’t exist.
409
ConflictThe client-generated id exists already, or the type isn’t part of the collection.

A resource is updated with a PATCH to its URL. The resource object needs a type and an id. Attributes and relationships that the request leaves out keep their current values, and the ones it has replace them.

HTTP request
PATCH /articles/1 HTTP/1.1
Content-Type: application/vnd.api+json
Accept: application/vnd.api+json

{
  "data": {
    "type": "articles",
    "id": "1",
    "attributes": {
      "title": "Hello, JSON:API"
    }
  }
}
Swift
// A new instance with the id sends only what changes
let changes = Article()
changes.id = "1"
changes.title = "Hello, JSON:API"

// PATCH articles/1
let updated = try await articles.update(changes).result()
200
OKThe server returns the updated resource, which it may have changed further, such as its updatedAt.
202
AcceptedThe update is accepted, but its processing isn’t complete yet.
204
No ContentThe resource was updated exactly as requested. Vox returns nil.
403
ForbiddenThe update is unsupported.
404
Not FoundThe resource, or a related resource, doesn’t exist.
409
ConflictThe type or id doesn’t match the endpoint, or the update violates a constraint.

A resource is deleted with a DELETE to its URL, which has no request document.

HTTP request
DELETE /articles/1 HTTP/1.1
Accept: application/vnd.api+json
Swift
// DELETE articles/1
try await articles.delete(id: "1").result()
200
OKThe resource is deleted, and the document has no primary data, but can have meta.
202
AcceptedThe deletion is accepted, but its processing isn’t complete yet.
204
No ContentThe resource is deleted, and there’s no document.
404
Not FoundThe resource doesn’t exist.

Local identifiers NEW IN 1.1

A resource created on the client can carry a lid, so that other resources in the same request document can refer to it before the server assigns an id. Once it has an id, Vox sends the id instead.

let author = Person()
author.lid = "new-author"
article.author = author
// "author": { "data": { "type": "people", "lid": "new-author" } }

Client-generated ids

A server can accept an id that the client generated, which must be universally unique, such as a UUID. A server that doesn’t accept it responds with 403 Forbidden.

let draft = Article()
draft.id = UUID().uuidString.lowercased()

// Still POST articles, with the id in the document
try await articles.create(draft).result()
Relationships

Change the links, not the resources

A relationship object can link to two endpoints. The related resource link returns the related resources themselves. The relationship link returns their linkage, and lets the client change the relationship directly: removing an author through it disconnects the person from the article, without deleting the person.

related

Related resource link

/articles/1/author returns the person as primary data. It stays valid when the relationship is empty, and doesn’t change when the relationship does.

self

Relationship link

/articles/1/relationships/author returns { "type": "people", "id": "9" }. It accepts PATCH, and for to-many relationships, POST and DELETE.

GET
/articles/1/authorThe related person
articles.fetchRelated("author", of: article, as: Person.self)
GET
/articles/1/commentsThe related comments, which can be sorted, filtered and paginated
articles.fetchRelated("comments", of: article, as: [Comment].self)
GET
/articles/1/relationships/tagsThe linkage of the tags
articles.fetchRelationship("tags", of: article, as: [Tag].self)
PATCH
/articles/1/relationships/authorReplaces the author, or removes it with nil
articles.updateRelationship("author", of: article, to: person)
PATCH
/articles/1/relationships/tagsReplaces every tag
articles.updateRelationship("tags", of: article, to: [swift, ios])
POST
/articles/1/relationships/tagsAdds the tags that aren’t there yet
articles.addToRelationship("tags", of: article, [concurrency])
DELETE
/articles/1/relationships/tagsRemoves the tags it lists
articles.removeFromRelationship("tags", of: article, [ios])

Each of these is a request, sent with try await request.result(). Vox follows the relationship’s related and self links, and without links, appends /author or /relationships/author to the path of the resource.

Errors

Problems, described

A server that can’t process a request can respond with error objects in a top-level errors array. It can stop at the first problem, or report several at once, such as one for each invalid attribute.

HTTP/1.1 422 Unprocessable Entity
{
  "errors": [{
    "status": "422",
    "source": { "pointer": "/data/attributes/firstName" },
    "title": "Invalid Attribute",
    "detail": "First name must contain at least two characters."
  }]
}

Error objects

An error object has at least one of these members.

id
A unique identifier for this occurrence of the problem.
links
about, with details of this occurrence, and type, which identifies the kind of error.
status
The HTTP status code, as a string.
code
An application-specific error code, as a string.
title
A short summary that doesn’t change between occurrences.
detail
An explanation of this occurrence.
source
A JSON Pointer to the value in the request that caused it, or the parameter or header.
meta
Non-standard meta-information.
Swift
do {
    let document = try await people.update(changes).result()
} catch JSONAPIError.API(let errors) {
    for error in errors {
        print(error.status ?? "", error.title ?? "")
        print(error.source?.pointer ?? "")
    }
} catch JSONAPIError.unacceptableStatusCode(let statusCode, _) {
    print("Status code", statusCode)
}

What Vox throws

JSONAPIError.API(errors)The server responded with error objects.
JSONAPIError.unacceptableStatusCodeThe status code is outside 200–299, and the response has no error objects.
JSONAPIError.invalidDocument(reason:)The response isn’t the expected document. The reason names the problem.
JSONAPIError.serialization(reason:)The request document or URL couldn’t be built, so nothing was sent.
URLErrorAnd the other errors of the client, when the request itself failed.

Add Vox to your app

Vox 2.0 requires Swift 6.1, which comes with Xcode 16.3 and later. It builds in the Swift 6 language mode with complete data-race checking, and its clients, data sources, requests and documents are Sendable.

        .upToNextMinor(from: "2.0.0")
    )
],
targets: [
    .target(name: "App", dependencies: [
        .product(name: "Vox", package: "Vox")
    ])
]
